### Problem 1: Inspect a user-process page table ###

What does each PTE logically represent, and what permissions does it have?

```
va 0xFFFFF000     trampoline    RX--
va 0xFFFFE000     trapframe     R-W-
...               ...           ...
va 0x3000         heap          R-WU
va 0x2000         stack         R-W-
va 0x1000         data          R-WU
va 0x0            text          RX-U
```

Differences from the book:

* In the output of `pgtbltest` the stack is marked as `R-W-`, while in the book it is `R-WU`.
* There is no guard page between the data segment and the stack.
* Is `MAXVA = 2^38 − 1` equal to `0xFFFF FFFF` or `0x3F FFFF FFFF`?

Notes:

The maximum offset within a page is 0x0FFF = 2^12 - 1 = 4096 - 1.
This means page contains 4096 addresses and each address corresponds to 1 byte.
Therefore, the page size is 4096 bytes (4 KB).

Why 0xFFFFFFFF is not equal to `MAXVA - 1`, even though it seems like it should be?



### Problem 3: Print a page table ###

For each leaf page, explain what it logically contains, what its permission bits are,
and how it relates to the output ot the earlier print_pgtbl() exercise above.

```
page table 0x0000000087f22000
 ..0x0000000000000000: pte 0x0000000021fc7401 pa 0x0000000087f1d000
 .. ..0x0000000000000000: pte 0x0000000021fc7001 pa 0x0000000087f1c000
 .. .. ..0x0000000000000000: pte 0x0000000021fc785b pa 0x0000000087f1e000
 .. .. ..0x0000000000001000: pte 0x0000000021fc6cd7 pa 0x0000000087f1b000
 .. .. ..0x0000000000002000: pte 0x0000000021fc6807 pa 0x0000000087f1a000
 .. .. ..0x0000000000003000: pte 0x0000000021fc64d7 pa 0x0000000087f19000
 ..0x0000003fc0000000: pte 0x0000000021fc8401 pa 0x0000000087f21000
 .. ..0x0000003fffe00000: pte 0x0000000021fc8001 pa 0x0000000087f20000
 .. .. ..0x0000003fffffd000: pte 0x0000000021fc7c13 pa 0x0000000087f1f000
 .. .. ..0x0000003fffffe000: pte 0x0000000021fd00c7 pa 0x0000000087f40000
 .. .. ..0x0000003ffffff000: pte 0x000000002000184b pa 0x0000000080006000
```

Here are the leaf pages: text, data, stack, heap, ... , usyscall, trapframe and trampoline.
And this exactly corresponds to the actual output of `print_pgtbl()`.

```
va 0x0 pte 0x21FC785B pa 0x87F1E000 perm 0x5B
va 0x1000 pte 0x21FC6C17 pa 0x87F1B000 perm 0x17
va 0x2000 pte 0x21FC6807 pa 0x87F1A000 perm 0x7
va 0x3000 pte 0x21FC64D7 pa 0x87F19000 perm 0xD7
...
va 0xFFFFD000 pte 0x21FC7C13 pa 0x87F1F000 perm 0x13
va 0xFFFFE000 pte 0x21FD00C7 pa 0x87F40000 perm 0xC7
va 0xFFFFF000 pte 0x2000184B pa 0x80006000 perm 0x4B
```

The permission bits are the last two hexadecimal digits of the PTE.

Notes:

For each program run, only the virtual addresses and permission bits remain constant.
The physical addresses and PTEs are reassigned for each new run.
